### 五张截图的拍摄脚本

1. **在网页旁边开始对话**：打开不含个人数据的公开页面；通过扩展图标打开侧栏；等待新临时草稿和当前页 chip 出现后拍摄。说明文案：“网页旁的助手，新草稿自动带上当前页”。
2. **用 @ 引用标签页**：准备两个公开示例页；展开 @ 候选列表。说明文案：“选择标签页，把网页上下文放进输入框”。
3. **把选中文字交给助手**：选中一段公开内容，通过实际引用入口加入输入框。说明文案：“选中文字，作为引用加入当前任务”。
4. **引用一个网页元素**：用准星拖动真实元素，分别捕捉轮廓或插入后的 chip。说明文案：“拖动准星，引用具体网页元素”。
5. **执行一个实际浏览器任务**：在测试页完成一次摘要或无敏感数据的页面操作。说明文案：“让助手读取页面并协助操作”。若尚未实际运行，不使用模型假回复作为截图。

截图应满幅、方角，保留能理解产品的浏览器上下文；不要放入私人标签标题、聊天、地址、Cookie、令牌、API Key、真实支付或健康记录。可用较大的演示字体，但不能把概念图当成功能截图，不使用 Google 官方徽章或未经授权的背书。

## 商店包与身份核对

### 本地手动安装包

`release/browse-extension-0.0.21.zip` 使用 `--unpacked` 构建，保留固定扩展 ID 和构建标记。商店包须按下方入口单独生成。

### 后续生成商店包时使用的入口

当前脚本 `scripts/package.ts`：稳定版执行 `bun run package` 会删除 manifest 的 `key` 和构建标记；`--unpacked` 保留手动安装身份。两条路径都写入同名 `release/browse-extension-版本号.zip`，会覆盖该路径的旧 ZIP。因此应先把需要保留的原手动包放到明确的归档位置，或先调整分开命名；不要在不知情的情况下覆盖交付物。

```bash
bun run package
```

此命令仅作后续执行说明，**本次未运行**。商店材料文档不应被额外塞进扩展运行包。

首次创建商店条目后，使用控制台分配的实际 ID 核对侧栏消息路由。桌面远控网页与扩展侧栏共用桌面主机的账号密码，浏览器调试服务的配对由扩展在后台处理。

## 建议提交顺序

1. 完成开发者账户资料，并确定公开支持渠道。
2. 确认商店发行版的数据传输和披露方案；必要时再做实现调整。
3. 生成最终商店 ZIP，上传为草稿并取得实际条目 ID，核对兼容主程序来源配置。
4. 准备公开可下载的兼容主程序及完整审核配置。
5. 确认并公开托管隐私政策；填写实际 URL。
6. 上传真实截图和宣传素材，粘贴商店介绍、单一用途与权限理由，确认数据类别。
7. 填入 reviewer-guide.md 的精确下载、账号／模型及视频信息后提交审核。

本次准备材料不包含上述外部发布动作，也不替你同意控制台声明或支付费用。
